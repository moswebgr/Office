# MosSuite roadmap

This roadmap is intentionally incremental. A feature is not considered complete until it is implemented, tested, and documented.

## Phase 1 — Project foundation
- [x] Create the project landing page.
- [x] Publish the initial product vision and application list.
- [x] Add an open-source license.
- [ ] Enable GitHub Pages and verify the published URL.
- [ ] Add issue templates and contribution guidelines.
- [ ] Decide on the first app based on the smallest useful end-to-end milestone.

## Phase 2 — First working application
- [x] Build a responsive first WriteFlow editor shell.
- [x] Add rich-text formatting, title editing, word/character counts, text import, HTML export and print.
- [x] Persist user work locally before introducing accounts or cloud sync.
- [ ] Add automated checks and a documented manual test checklist.
- [ ] Test across browsers and mobile devices; publish a demo only after verification.

## Phase 3 — Documents and data
- [x] WriteFlow first milestone: editing, local save/load, plain-text/Markdown import and HTML export.
- [ ] WriteFlow next: robust Markdown export, undo/redo review, accessibility and browser tests.
- [ ] GridForge: editable grid, basic formulas, CSV import/export.
- [ ] NoteHarbor: notebooks, tags, search, export/import.

## Phase 4 — Presentations and planning
- [ ] SlideSpark: create, edit, reorder and present slides.
- [ ] PlanPilot: tasks, due dates, board and calendar views.
- [ ] DiagramDock: shapes, connectors, save/load and export.

## Phase 5 — Collaboration and integrations
- [ ] MailNest: documented email-provider support and secure credential handling.
- [ ] CloudShelf: storage provider integrations and clear data ownership controls.
- [ ] MeetMesh: chat prototype, then real-time infrastructure and security review.
- [ ] DataNest: tables, forms, CSV import/export and data validation.

## Definition of done
A feature is done only when it has:
1. Working implementation—not just a mockup.
2. Clear setup and usage instructions.
3. Tests or reproducible manual verification.
4. Accessible and responsive behavior.
5. Known limitations documented.
